# ADR 001. SQLite как база данных

## Контекст

Проекту нужна база данных для пользователей, контактов, очередей и звонков.
Проект демонстрационный: его должен мочь запустить человек, который
«ничего не знает в программировании», — без установки сервера баз данных
и без настройки подключений.

## Варианты

1. **PostgreSQL** — стандарт индустрии, богатые возможности. Но требует
   установки отдельного сервера, настройки пользователя/пароля, запуска службы.
2. **MySQL** — похоже на PostgreSQL по «стоимости входа».
3. **SQLite** — база данных в одном файле, встроена в Node.js (модуль
   `node:sqlite` начиная с Node 22.5). Нативная компиляция не требуется.

## Решение

Использовать **SQLite** через встроенный модуль `node:sqlite`.

## Последствия

**Плюсы:**
- Запуск «из коробки»: база — просто файл, никаких серверов.
- Нет внешних зависимостей для старта — идеально для демо.
- Слоистая архитектура изолирует SQL в репозиториях, поэтому переход на
  PostgreSQL позже затронет только папку `db/` и репозитории.

**Минусы и ограничения:**
- SQLite — один писатель за раз. Для демо и малых нагрузок это не проблема,
  но при высокой конкурентной записи её нужно заменить.
- В `docker-compose.yml` нет отдельного контейнера с базой — данные живут
  в томе `voxdesk-data`.

## Когда менять решение

При переходе на высокие нагрузки или если потребуется репликация и
одновременная запись из многих процессов — заменить на PostgreSQL
(см. [ARCHITECTURE.md](../ARCHITECTURE.md#куда-развивать-дальше)).
