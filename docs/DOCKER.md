# Запуск VoxDesk в Docker

Docker упаковывает приложение вместе со всем окружением, поэтому запуск не
зависит от того, что установлено на компьютере. В этом проекте — два образа:
backend (Node.js) и frontend (nginx со статикой).

> Docker **не обязателен**: проект запускается и напрямую через Node.js
> (см. [../README.md](../README.md)). Docker — альтернатива для тех, кому
> удобнее «одна команда — весь стек».

---

## Требования

- Docker Desktop (или Docker Engine) с поддержкой `docker compose`.

## Запуск

```powershell
cd voxdesk
docker compose up --build
```

После сборки откройте **http://localhost:8080** — frontend сам проксирует
запросы `/api` на backend, поэтому фронтенд и API работают на одном адресе
(нет проблем с CORS и проще с куками).

Остановить: `Ctrl+C`. Остановить и удалить контейнеры: `docker compose down`.
Удалить вместе с данными БД: `docker compose down -v`.

---

## Как устроены образы

### Backend (`backend/Dockerfile`)

Многоступенчатая сборка:

1. **builder** — устанавливает все зависимости и компилирует TypeScript в
   JavaScript (`npm run build`).
2. **runner** — берёт только собранный код и продакшн-зависимости
   (`npm ci --omit=dev`). В итоговом образе нет компилятора и dev-инструментов
   — он меньше и безопаснее.

Контейнер работает не от root, а от пользователя `node`.

### Frontend (`frontend/Dockerfile`)

1. **builder** — собирает статику Vite (`npm run build`).
2. **runner** — nginx, который раздаёт статику и проксирует `/api`.

Конфиг nginx (`frontend/nginx.conf`) решает три задачи: раздача статики,
SPA-фолбэк (чтобы `/calls` и `/contacts` открывались при перезагрузке страницы)
и проксирование API.

## Данные и их сохранение

SQLite — это файл базы, а не отдельный сервер, поэтому **третьего контейнера
с базой нет**. Файл лежит в именованном томе `voxdesk-data`, и данные
сохраняются между перезапусками контейнеров.

- Посмотреть том: `docker volume ls`
- Полностью сбросить данные: `docker compose down -v`

## Переменные окружения

В `docker-compose.yml` переменные заданы прямо в описании сервиса
(для локального запуска). В реальном окружении секреты (`JWT_*`, пароль
администратора) передаются через `.env` или секрет-хранилище и **не
коммитятся** в репозиторий.

## Полезные команды

```powershell
docker compose logs -f backend     # смотреть логи backend
docker compose ps                  # статус контейнеров
docker compose up --build backend  # пересобрать только backend
```
