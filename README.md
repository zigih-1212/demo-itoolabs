# VoxDesk — облачная АТС и колл-центр для B2B

VoxDesk — демонстрационный fullstack-проект: система для компаний, которая
показывает работу колл-центра. Операторы принимают и совершают звонки,
супервайзеры распределяют нагрузку по очередям и смотрят аналитику,
администратор управляет сотрудниками. Проект сделан по мотивам реальных
продуктов для B2B-телефонии и полностью запускается «из коробки».

---

## Что внутри (кратко)

| Часть | Технологии | Зачем именно они |
| --- | --- | --- |
| **Frontend** | Vue 3, TypeScript, Vite, Pinia, Vue Router, SCSS | Vue — простой и популярный фреймворк; TypeScript ловит ошибки до запуска; Vite даёт быструю сборку |
| **Backend** | Node.js, Express, TypeScript, Zod, JWT | Express — понятный и распространённый сервер; Zod проверяет входящие данные; JWT — безопасный вход |
| **База данных** | SQLite (встроенный модуль `node:sqlite`) | Не требует установки отдельного сервера — база это просто файл. Идеально для демо и локального запуска |
| **Логи и защита** | pino, helmet, rate-limit, bcrypt | Структурные логи, защитные HTTP-заголовки, ограничение частоты запросов, хэширование паролей |

Проект — **монорепозиторий** на npm workspaces: `backend/` и `frontend/`
живут рядом и собираются общими командами из корня.

## Быстрый старт (5 минут)

> Нужен только **Node.js 22.5 или новее** (проверить: `node -v`). Docker
> и отдельная база данных не требуются.

```powershell
# 1. Перейти в папку проекта
cd voxdesk

# 2. Установить зависимости (один раз, это может занять пару минут)
npm install

# 3. Создать файлы настроек из шаблонов
Copy-Item .env.example .env
Copy-Item backend\.env.example backend\.env

# 4. Создать таблицы в базе и наполнить её демо-данными
npm run db:migrate
npm run db:seed

# 5. Запустить backend и frontend одновременно
npm run dev
```

После запуска откройте в браузере **http://localhost:5173**.

Всё это есть и одной командой: `npm run setup` (установка + миграции + данные).

### Демо-доступы

Пароль у всех одинаковый: `demo12345`. На странице входа есть кнопки, которые
подставляют данные в один клик.

| Роль | E-mail | Что видит |
| --- | --- | --- |
| Администратор | `admin@voxdesk.local` | Всё: сотрудники, очереди, аналитика, настройки |
| Супервайзер | `supervisor@voxdesk.local` | Очереди, команда, аналитика (без управления сотрудниками) |
| Оператор | `agent1@voxdesk.local` | Дашборд, звонки, контакты |

## Что есть в приложении

- **Дашборд** — сводка за период: всего звонков, отвечено, пропущено, средняя
  длительность, график активности по дням, рейтинг операторов и лента событий.
- **Журнал звонков** — список с фильтрами по направлению и статусу, карточка
  звонка с деталями, создание звонка.
- **Контакты** — справочник клиентов с поиском, тегами и сортировкой.
- **Очереди** — группы распределения звонков (три стратегии: дольше всех ждёт,
  по кругу, все одновременно), включение/выключение очереди.
- **Команда** — управление сотрудниками: роли, статусы, создание и удаление.
- **Аналитика** — нагрузка по часам, загрузка очередей, эффективность
  операторов, лента событий.
- **Настройки** — профиль и краткая сводка по системе.

У каждого пользователя свой набор разделов: оператор не увидит аналитику,
а супервайзер — управление сотрудниками. Это проверяется и на клиенте
(меню, маршруты), и на сервере (каждый защищённый эндпоинт).

## Команды

Запускать из корня `voxdesk/`. Суффикс `--workspace` позволяет обратиться
к конкретному пакету, например `npm run test --workspace @voxdesk/backend`.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Запускает backend и frontend параллельно (режим разработки) |
| `npm run dev:api` | Только backend (http://localhost:4000) |
| `npm run dev:web` | Только frontend (http://localhost:5173) |
| `npm run build` | Собирает production-версии обеих частей |
| `npm test` | Запускает тесты |
| `npm run lint` | Проверяет код линтером |
| `npm run typecheck` | Проверяет типы TypeScript |
| `npm run db:migrate` | Создаёт таблицы в базе |
| `npm run db:seed` | Наполняет базу демо-данными |
| `npm run db:reset` | Удаляет файл базы (чистый старт) |

## Переменные окружения

Настройки лежат в двух файлах `.env` (корень и `backend/`), создаются из
`.env.example`. Что важно:

| Переменная | Смысл |
| --- | --- |
| `PORT` | Порт backend (по умолчанию 4000) |
| `DATABASE_PATH` | Путь к файлу базы данных |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` | Секреты для подписи токенов. **В продакшене обязательно сменить** |
| `JWT_ACCESS_TTL` / `JWT_REFRESH_TTL` | Время жизни токенов доступа и обновления |
| `BCRYPT_ROUNDS` | «Сложность» хэширования пароля |
| `CORS_ORIGIN` | Адрес фронтенда, которому разрешены запросы |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | Данные администратора при первичном наполнении |

> Секреты (пароли, ключи) никогда не коммитятся: файлы `.env*` уже в
> `.gitignore`. В репозиторий попадает только `.env.example` — шаблон без
> настоящих значений.

## Запуск в Docker (необязательно)

Если есть Docker, можно поднять весь стек одной командой — без установки
Node.js. Подробности и объяснение образа — в [docs/DOCKER.md](docs/DOCKER.md).

```powershell
cd voxdesk
docker compose up --build
```

Приложение будет доступно на **http://localhost:8080**.

## Структура проекта

```
voxdesk/
├── backend/                 # Серверная часть (API)
│   ├── src/
│   │   ├── config/          # Чтение и проверка настроек (env.ts)
│   │   ├── db/              # Схема БД, подключение, миграции, сиды
│   │   ├── domain/          # Типы предметной области
│   │   ├── lib/             # Утилиты: логи, ошибки, токены, пагинация
│   │   ├── middleware/      # Промежуточные слои Express (auth, валидация…)
│   │   ├── modules/         # Бизнес-модули (auth, users, calls, …)
│   │   ├── app.ts           # Сборка Express-приложения
│   │   └── index.ts         # Точка входа: старт сервера
│   └── tests/               # Тесты API
├── frontend/                # Клиентская часть (SPA)
│   └── src/
│       ├── api/             # Слой обращения к backend
│       ├── components/      # Переиспользуемые компоненты
│       ├── composables/     # Переиспользуемая логика (например, confirm)
│       ├── router/          # Маршруты и защита доступа
│       ├── stores/          # Состояние приложения (Pinia)
│       ├── styles/          # Дизайн-токены, миксины, базовые стили
│       ├── utils/           # Форматирование, метки, хелперы
│       └── views/           # Страницы
├── docs/                    # Документация (архитектура, решения, Docker)
├── worker/                  # Edge-двойник API для Cloudflare (демо-стенд)
├── wrangler.jsonc           # Конфигурация деплоя на Cloudflare Workers
├── docker-compose.yml       # Запуск всего стека в Docker
└── README.md                # Этот файл
```

Ключевая идея backend: **слои**. Запрос проходит путь
`routes → controller → service → repository → база`. Каждый слой занят своим
делом (см. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)).

## Публичный демо-стенд (Cloudflare)

Живая версия демо развёрнута на **Cloudflare Workers** — это serverless-хостинг,
который не требует держать свой сервер. Основной backend написан на Node.js +
`node:sqlite`, а на edge-платформе Node-сервер запустить нельзя, поэтому для
демо-стенда сделан «edge-двойник» API: та же схема, те же пути и формат ответов,
но на Cloudflare-технологиях (Worker + база **D1**). Фронтенд при этом не
меняется вовсе — он просто обращается к `/api/...`.

- **Стенд:** https://voxdesk.dvybornyh332.workers.dev
- **Демо-доступы:** те же, что и локально (см. раздел «Что есть в приложении»).

Почему так, что это за компромисс и как повторить деплой — в
[docs/adr/007-edge-deployment.md](docs/adr/007-edge-deployment.md).

Команда для повторного деплоя (из папки `voxdesk`):

```powershell
npm --workspace frontend run build
$env:CLOUDFLARE_API_TOKEN="<ваш токен>"
$env:CLOUDFLARE_ACCOUNT_ID="<ваш account id>"
npx wrangler deploy
```

Исходники edge-двойника — в папке [`worker/`](worker/), конфигурация — в
[`wrangler.jsonc`](wrangler.jsonc).
